# Virtual Lab Simulator v3 — Line-by-Line Flow

## What changed

The simulator no longer uses the old sparse execution trace as the visible step sequence.
The student now receives **one stable walkthrough step for every physical source-code line**, in source order.

Existing `simulationData.steps` entries are still used when a source line already has detailed practical-specific information. Lines without a trace entry receive a deterministic explanation generated by `frontend/js/simulator/engine.js`.

## Student controls

- **Back** — move exactly one source line backward.
- **Next** — move exactly one source line forward.
- **Play** — automatically advance one line at a time.
- **Pause** — stop automatic advancement without resetting.
- **Restart** — return to line 0.
- **Finish** — move to the final source line.
- **Arrow Left / Arrow Right** — Back / Next.
- **Space** — Play / Pause.
- **Home / End** — Restart / Finish.

## Anti-jump / anti-lag design

1. The complete source code is converted to a stable step array once when the simulator is created.
2. The source-code DOM rows are created once and reused.
3. A single `setTimeout` is used for Play mode; there is never an accumulating interval stack.
4. Pausing/canceling increments a run token so an old timer cannot continue the walkthrough.
5. Only the simulator's internal code pane is adjusted to reveal the current line. The whole page is never scrolled automatically.
6. Moving Back does not recalculate or replay the program; it simply changes the cursor to a previously generated snapshot.
7. No hidden source-line jump occurs between two visible steps.

## Important learning behavior

A source line with an existing detailed runtime trace shows that authored `What / Why / How / Result` information. A source line without one is still shown and explained, but the UI explicitly labels it as a walkthrough explanation rather than inventing a hidden runtime event.

This distinction is intentional: it makes the flow continuous without pretending that a sparse trace contains execution information it does not actually contain.

## v3.1 Output & Record Result

The simulator output panel is now a real student-facing result area, not a placeholder:

- **This line produces** shows the console contribution of the current line when trace data provides one.
- **Console — output so far** keeps a running terminal-style transcript as the learner advances.
- `[space]` and `[newline]` trace markers are rendered as real spaces/newlines; escaped `\\n` and `\\t` are also rendered correctly.
- **Final Answer / Result** appears when the full source walkthrough is complete and shows the practical's `finalOutput` (falling back to `expectedOutput` when needed), explicitly labelled as the result to write in the practical record.
- Lines that do not print still leave the accumulated console visible, so students can see that processing continues without pretending that every source line produces output.
- When the old runtime trace repeats the same physical source line, the walkthrough uses the first occurrence for that physical line rather than jumping to a later loop iteration. The final record answer remains the authoritative complete result.
